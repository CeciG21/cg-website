Delivery Lens

A portfolio example exploring evidence-grounded Agile delivery intelligence, using read-only Azure DevOps data, historical snapshots and optional AI-assisted explanations.

Next.js + TypeScriptAzure DevOpsPostgreSQLOptional AI
THE ENGINEERING PROBLEM

Historical delivery evidence can be difficult to reconstruct.

Today’s board state does not reliably show what was planned at sprint start, what moved afterwards, or which release signals have supporting evidence.

THE APPROACH

Reconstruct the facts before interpreting them.

Delivery Lens explores point-in-time evidence, explicit scope movement and separated release states so dashboards and optional AI briefings can be based on the same verified snapshot.

ENGINEERING CONSIDERATIONS

Evidence first; interpretation second.

01

Point-in-time baselines

Historical ASOF queries help reconstruct work-item membership at the selected cutoff.

02

Visible scope changes

Added and removed work are separated so a stable total cannot conceal significant movement.

03

Bounded AI explanation

Missing evidence remains unknown. Optional AI can explain the same verified snapshot without inventing facts.

DESIGN PRINCIPLES

What this example demonstrates

Historical accuracy

Represent what was true at a known cutoff instead of silently substituting current state.

Uncertainty

Show missing evidence as unknown rather than making false numeric or narrative conclusions.

Read-only integration

Read evidence from Azure DevOps without modifying the delivery source records.

AI with boundaries

Use optional AI to interpret verified evidence, not create data unsupported by the source.
