Delivery Lens

An evidence-grounded delivery intelligence layer for Agile software projects, using read-only Azure DevOps data, historical snapshots and optional AI explanations.

Next.js + TypeScriptAzure DevOpsPostgreSQLOptional OpenAI
THE PROBLEM

Delivery conversations often begin with opinion because historical evidence is hard to reconstruct.

Today’s board state cannot reliably answer what was planned at sprint start, what moved later, or whether a release signal is genuinely proven.

THE APPROACH

Reconstruct the facts before asking what they mean.

Delivery Lens uses point-in-time evidence, explicit scope movement and separated release states so the dashboard and optional AI briefing start from the same server-side snapshot.

WHY IT’S USEFUL

Evidence before opinion.

01

Recover what was actually planned

Historical ASOF queries reconstruct exact baseline membership rather than judging a sprint only from today’s board state.

02

Expose scope churn honestly

Added and removed work are measured separately so unchanged totals cannot hide significant movement.

03

Keep facts separate from interpretation

Unknown evidence remains unknown. Optional AI explains the same verified snapshot and is instructed not to invent certainty.

DESIGN PRINCIPLES

What the product is optimised for

Point-in-time truth

Represent what was true at the configured cutoff instead of silently substituting current state.

Explicit uncertainty

Missing or insufficient evidence is shown as unknown rather than converted into a false zero or confident conclusion.

Read-only integration

Use Azure DevOps as an evidence source without turning the analysis tool into another place that mutates delivery records.

AI with boundaries

Use AI to explain verified evidence, not to create facts that the source data cannot support.
